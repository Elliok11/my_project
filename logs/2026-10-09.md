## ⚠️ 卡住点（本日主要工作）：`ollama run` 启动即崩溃

### 现象

```
> ollama pull qwen2.5:1.5b
success                         ← 模型下载成功

> ollama run qwen2.5:1.5b
Error: 500 Internal Server Error: llama-server process has terminated:
exit status 0xc0000005: The instruction at 0xp referenced memory at 0xp.
```

### 排查过程（按顺序）

**1. 排除模型文件损坏**
`sha256 digest` 校验通过；重新 `pull` 两次现象完全相同 → 与模型文件无关。

**2. 排除"虚拟机缺少 AVX 指令集"**
执行 `systeminfo`，输出**没有**"已检测到虚拟机监控程序"一行 → 是物理机。
机型 Dell Inspiron 5548，CPU 为 `Family 6 Model 61`（i5-5200U / Broadwell），**原生支持 AVX2**
→ 不是指令集缺失问题。

**3. 排除"系统缺少 VC++ 运行库"**
自查 `C:\Windows\System32\vcruntime140.dll` → 版本 14.44.35211.0，注册表中 x64 运行库为 v14.44.35211
→ 运行库完整且为较新版本，排除。

**4. 关键突破：读 Windows 事件日志**
命令：查看"应用程序"日志中事件 ID 1000（应用程序错误），筛选 ollama/llama 相关记录。

```
错误应用程序名称: llama-server.exe
错误模块名称:     vulkan-1.dll          ← 崩溃发生在这个模块
异常代码:         0xc0000005
错误偏移量:       0x0000000000040494
```

→ 结论：不是 CPU、不是内存、不是模型，而是**显卡相关的 Vulkan 初始化崩溃**。

**5. 读 Ollama 引擎日志，看清它在干什么**
用 `OLLAMA_DEBUG=1` 启动服务并重定向日志，抓到关键几行：

```
load_tensors: offloading output layer to GPU
load_tensors: offloading 16 repeating layers to GPU
load_tensors: offloaded 17/29 layers to GPU
load_tensors:   CPU_Mapped model buffer size =   934.69 MiB
load_tensors:      Vulkan0 model buffer size =   605.40 MiB
load_tensors: Load failed ... exit status 0xc0000005
```

→ Ollama 把 29 层模型中的 19 层**卸载到了一块叫 `Vulkan0` 的显卡上**，然后崩了。

**6. 查证 `Vulkan0` 到底是谁**

- 注册表 `HKLM\SOFTWARE\Khronos\Vulkan\Drivers`（Vulkan 驱动注册表）**不存在** → 没有任何 ICD 注册
- 但在 `C:\Windows\System32\DriverStore\...\B360357\` 找到 `amd-vulkan64.json` +
  `amdvlk64.dll`，`api_version: 1.2.133`
- 系统里的 `vulkan-1.dll` 为 2020 年的 1.2.131.2，且**公司名为空**
- 注册了两个指向 `C:\Users\Administrator\steam\` 的 Vulkan 隐式层，
  其中一个（fossilize）的 DLL **根本不存在**（悬空注册），另一个声明 `api_version: 1.4.303`，
  远高于加载器支持的 1.2.131

→ 结论：本机 AMD Radeon R7 M260（2013 年显卡，2 GB 显存，驱动停留在 2020 年）
的 Vulkan 实现**极其不可靠**，而 Ollama 默认把它当成了可用加速卡。

### 6 组对照实验（定位解法）

| # | 环境变量配置 | 结果 | 是否有 GPU 卸载 |
|---|---|---|---|
| 1 | 默认（不设任何变量） | ❌ 崩溃 | offloaded 19/29 layers |
| 2 | `OLLAMA_VULKAN=0` | ✅ 成功 | 无 |
| 3 | `OLLAMA_VULKAN=false` | ✅ 成功 | 无 |
| 4 | `OLLAMA_LLM_LIBRARY=cpu` | ✅ 成功 | 无 |
| 5 | `GGML_VK_VISIBLE_DEVICES=`（空） | ❌ 崩溃 | offloaded 19/29 layers |
| 6 | `VK_DRIVER_FILES=C:\__no_icd__.json` | ❌ 崩溃 | offloaded 19/29 layers |

### 解决方案

```cmd
setx OLLAMA_VULKAN 0
```

永久写入用户级环境变量（`HKCU\Environment`），重启后依然有效。

### 验证结果

```
qwen2.5:1.5b → 生成速度 12.88 tokens/秒
中文对话正常：我是一个能够理解和生成文本的AI助手...
计算题正常：1+1=? → 2
纯 CPU 运行，日志中无任何 GPU 卸载记录
```

## 我犯的三个错误（也要记录）

1. **误判"Ollama 版本过旧"**
   最初认为 0.40.2 是老版本，建议升级。经查 Ollama 官方仓库确认 **v0.40.2 发布于 2026-10-08，就是最新版**。
   这个错误是**用户质疑后**才纠正的。
   **教训：不要凭经验猜测软件版本，直接查官方发布记录。**

2. **第一次 `OLLAMA_VULKAN=0` 实验得出错误结论**
   当时托盘程序已占用 11434 端口，测试请求实际打到了旧实例上，因此误判"该变量无效"。
   **教训：做对照实验必须保证测试环境隔离（换端口、清进程、确认监听者）。**

3. **`Start-Process -Environment` 参数不存在**
   该参数在较旧版本 PowerShell 中不支持，报错后改为在会话内设置环境变量解决。
