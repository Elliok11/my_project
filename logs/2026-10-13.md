## 今天做完的

写完了排程内核 `scheduler/`，**不依赖任何大模型**，只用 Python 标准库：

| 文件 | 干什么 |
|---|---|
| `model.py` | 事件模型（一次性 / 每周重复 + 截止日期 / 前置准备时间）+ 校验 |
| `store.py` | 追加式 JSONL 存储（只新增不重写，能看 git diff） |
| `conflict.py` | 三类冲突检测、找空档、提议替代方案 |
| `ics.py` | 导出 `.ics`（折行、转义、RRULE） |
| `cli.py` | 命令行：`demo` / `week` / `verify` / `gaps` / `check` / `add` / `ics` |
| `tests/` | 35 个单元测试，全绿 |

### 核心设计：把职责劈成两半

```
模型  →  提议（propose）：从自然语言里抽取事件、提出候选时间
内核  →  裁决（decide） ：这个时间到底成不成立，只有这里说了算
```

**内核里没有任何模型调用、没有任何随机性。** 同一份输入永远得到同一个答案。
理由：模型那点不确定性，必须被一层确定性的验证夹在中间。这也是我做这个作品的**实验假设** ——
第 5 天要用 20 条真实输入去验证它（纯 LLM vs LLM+内核）。

### 冲突分三类，严重程度不同（这是我认为最有价值的设计）

| 类型 | 含义 | 处理 |
|---|---|---|
| `overlap` | 时间真的重叠 | 硬冲突，必须解决 |
| `travel` | 上一件结束到下一件开始不够赶路 | 硬冲突（跨校区） |
| `prep` | 前置准备时间和别的事撞了 | 硬冲突 |
| `overload` | 一天排太多，精力不够 | **只警告，不阻止** |

`overload` 故意不阻止，因为"今天四件事算不算多"只有人自己知道。
**工具的职责是把事实摆出来，不是替人做决定。**

## ⚠️ 今天踩的坑（这部分才是重点）

### 坑 1：`travel` 在重叠时误报一次"负数分钟"

第一次跑 demo，同一对事件被报了两遍：

```
❌ 时间重叠：10-15 19:00-20:30 大学体育 与 10-15 19:30-20:30 班会 撞在一起，重叠 60 分钟。
❌ 赶不上：大学体育 20:30 结束，班会 19:30 开始，只有 -60 分钟，但 体育馆 → 东区 A201 需要 10 分钟。
```

那条 `-60 分钟` 是破绽：**负数说明代码压根没意识到这两件事已经撞了**。
原因是我把"重叠检查"和"赶路检查"写成两个独立循环，各报各的。

对策：先找出真正重叠的事件对，赶路检查跳过这些对。
**同一个事实报两遍就是噪声，一个满是噪声的工具没人敢用。**

### 坑 2：`prep` 被 `overlap` 吞掉 —— 两种不同的"病"报成了同一条

面试要提前 60 分钟准备（14:00 起忙），而 14:00 有课。这条被报成了普通"时间重叠"。
但这两件事**病因不同、解法也不同**：前者要往前挪准备时间，后者要改期。

对策：两者分开成 `overlap` 和 `prep` 两种 kind，各报各的。

（顺便：我一度以为"12:00 的课到 13:40 结束"也会撞上 14:00 的准备时间，
自己算了一遍才发现中间还有 20 分钟空隙、**其实不冲突**。内核比我的算术准。）

### 坑 3：`.ics` 折行 —— 这个函数我写错了四版 ⭐

这是今天最值钱的一个坑。RFC 5545 规定一行不超过 75 **字节**，续行以空格开头，
且**切点必须落在字符边界上**（中文一个字 3 字节，按字符折会超限）。

四版的错误分别是：

| 版本 | 错在哪 |
|---|---|
| ① | 只回退结尾的"续字节"。切点落在**首字节**上时留下半截字符（有头没身） |
| ② | 想补"首字节也回退"，写成 `(trail & 0xC0) == 0xC0`。可 `0xAC & 0xC0 == 0xC0` 同样成立，**续字节被误判**，回退循环一路啃到底，把完整汉字的头也啃掉了 |
| ③ | 只管"尾巴别切坏"，没管"下一段会从续字节开头" |
| ④ | **计数差一位**：辅助函数返回的是"包含第 `pos-1` 字节的字符的起点"，我却拿它判断"前 `pos` 个字节合不合法" —— 看起来在做边界处理，实际上一次都没生效过 |

**最后是怎么收敛的**：别再自己推算 UTF-8 的长度规律，改用不变量 ——

> "能不能切在这里" ≡ "前 n 个字节能不能解码成合法 UTF-8"。
> **这个判断交给解码器去做，逻辑立刻变得不可能写错。**

这个 bug 特别坏的地方：**切出来的字节总数一个不差**，
所以任何"检查行长"的测试都发现不了它，只有"折完拼回去、逐字节比对"才抓得住。
而且它只在"中文 + 长度刚好卡在边界"时出现 —— 只测一两个长度会整片躲过去。
所以我把测试改成了**对 1~120 个字符的长度全部试一遍**。

### 坑 4：多星期重复只展开了第一个星期几

`weekdays=[1,4]`（周一和周四）的体育课，周四整个消失了。
原因是我用 `min(...)` 只取了"离起始日最近的那个 weekday"。
对策：对每一个 weekday 各自算一个序列，再合并排序。

**这个 bug 平时发现不了** —— 只有当一条事件真的跨多个星期几时才暴露。

### 坑 5：裁决时把"库里的历史问题"倒给了用户

裁决"把班会改到周三"时，输出里混进了库里**原本就存在**的"周四体育撞班会"。
用户会以为是这次改动引起的。

对策：加 `issues_touching()`，裁决一个提议就**只报和这个提议有关的冲突**；
库里的历史问题交给 `verify` 命令单独负责，各管一摊。

### 坑 6：替代方案推荐了"那天已经排爆了"的时间

最早的版本会推荐 22:15 这种深夜时段，而那天本来就排了 7 件事 ——
数学上不冲突，但人不会接受。

### 坑 7（设计错误，不是代码错误）：优先级没定义清楚

原定"周三 19:30"，程序把"周五 08:00"排在"周五 19:30"前面。
对一个已经约好的会来说，"周五同一时刻"明显比"周五早上八点"更容易接受。

**原因不是排序代码写错了，而是优先级本身没定义清楚** ——
我把"同一天优先"和"同时间优先"混成了一个 `preferred` 布尔值。
改成三档显式的 tier 之后，排序就变成不需要动脑的事：

```
tier 0：同一天、时刻也差不多   （只动时间，不惊动别人）
tier 1：换一天、但时刻不变     （只挪日期，别人不用重新记时间）
tier 2：换一天、时刻也变       （改动最大）
```

### 坑 8：自检失败时，旧文件留在原地，没人发现

样例数据脚本加了自检（"这份数据必须能触发预期的那几类冲突"）。
某次自检失败 → 脚本在**写文件之前**就退出了 → 磁盘上还是上一版的旧文件。
后来我用 `verify` 扫的时候怎么扫都扫不到冲突，白查了一轮才发现是文件没更新。

**教训：只检查"将要写什么"是不够的，还要检查"磁盘上实际留下了什么"。**
对策：加 `_check_raw_file()`，绕开数据模型直接读原始 JSON，专门盯锚点日期对不对；写完再验一遍。

另外还有两个小坑：

- Windows 控制台默认 GBK，输出 emoji 直接 `UnicodeEncodeError` → 在 import 阶段把 stdout 顶成 UTF-8
- demo 数据不重置，跑第二遍时新旧事件同时存在，看起来像 bug，其实是脏数据

## 一个实验方法上的坚持

样例数据里**故意放了一条"不该报"的**（周三 10:00 在东区、13:00 在西区，中间 1 小时够赶路），
用来证明检查器只抓真问题、不制造噪声。

> **一个只会喊"你有冲突"的工具没人敢用；一个能分清"这个不用管"的才敢用。**

而且样例脚本里加了自检：生成完必须真的能触发 `overlap` 和 `overload`，
否则直接报错退出 —— 防止哪天数据被改动后，README 还在说"看，它抓到了冲突"。

## 实测效果

```
$ python -m scheduler -s scheduler/examples/schedule_demo.jsonl verify 2026-03-02 --days 21

  ❌ 时间重叠：03-05 19:00-20:30 大学体育 与 03-05 19:30-20:30 班会 撞在一起，重叠 60 分钟。
  ❌ 时间重叠：03-06 14:00-15:40 线性代数 与 03-06 15:00-16:00 人工智能协会二面 撞在一起，重叠 40 分钟。
  ⚠️  03-04（周三）排了 6 件事，共 7 小时 10 分钟，超过设定的 5 件上限。

合计：硬冲突 4 条，提醒 3 条。
```

```
$ python -m scheduler -s .../schedule_demo.jsonl check "班会改期" 2026-10-14T19:30 -d 60 -l "东区 A201"

❌ 这样安排不行
   ❌ 时间重叠：10-14 19:00-20:30 社团例会 与 10-14 19:30-20:30 班会改期 撞在一起，重叠 60 分钟。
   建议改到：
   → 10-16 周五 19:30-20:30（只挪日期）
   → 10-17 周六 19:30-20:30（只挪日期）
```

注意最后那个建议：**时刻不变、只挪一天** —— 这是对人打扰最小的方案。
